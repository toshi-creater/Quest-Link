# QuestLink 要件定義書

---

## 1. プロダクト概要

QuestLink は、オンラインゲームで「今すぐ一緒にプレイする相手」を即時に見つけられる Web アプリケーションである。

| 項目 | 仕様 |
|------|------|
| 対応プラットフォーム | Web（PC・モバイルブラウザ両対応） |
| トップ画面 | おすすめゲームカテゴリと部屋一覧を表示するトップページ（`/`）。ゲームカテゴリ選択でゲーム別部屋一覧へ遷移 |

### ポジショニング

X・Discord を競合ではなく補完ツールとして位置づける。X・Discord 上でQuestLink の参加リンクをシェアし、外部からアプリの募集部屋に参加できる導線を提供する。

---

## 2. 機能要件

### 2.1 機能一覧・概要

| 機能 | 概要 | MVP |
|------|------|-----|
| ユーザー登録・認証 | Google / X / Discord の OAuth 2.0 ソーシャルログイン | ◯ |
| プロフィール管理 | ユーザー名・アイコン・自己紹介・プレイスタイルタグ・ゲームタイトルの設定（Discord Webhook URL の設定は**未実装**） | ◯ |
| 部屋作成 | ゲームタイトル・最大人数・プレイスタイル・募集文を設定して部屋を作成 | ◯ |
| 部屋情報編集 | 作成後に最大人数以外の部屋情報を編集可能 | ◯ |
| ゲーム選択 | 部屋一覧の前段。マスター登録済みタイトルから選択（スキップ不可・ログイン不要） | ◯ |
| 部屋一覧 | 選択ゲームで絞り込んだ部屋を新着順で一覧表示（画面更新時に最新化・ポーリングなし） | ◯ |
| 部屋一覧フィルター | プレイスタイル・空き枠あり/なし・フリーワード（部屋名・募集文）でフィルタリング | ◯ |
| 参加前プレビュー | 部屋の情報・参加者一覧・評価スコアをログイン不要で閲覧（画面更新時に最新化） | ◯ |
| 部屋参加 | 最大人数未満の部屋に参加。重複参加・満員時はエラー表示。募集リンク経由はゲスト参加可 | ◯ |
| ゲスト参加 | 募集リンク経由のみ。一時 ID を発行し表示名を入力（初期値はゲスト ID）。チャット参加可 | ◯ |
| リアルタイムチャット | WebSocket ベース。ログイン済み参加者およびゲスト参加者が利用可 | ◯ |
| 部屋退出 | 任意のタイミングで退出可能。ログイン済みは評価画面へ遷移、ゲストはログイン促進画面へ遷移 | ◯ |
| ホスト移譲 | ホスト離脱時に最も早く参加した**ログイン済み**ユーザーへ自動引き継ぎ | ◯ |
| キック | ホストが参加者（ログイン済み・ゲスト両方）を強制退室させる。キック対象の画面は自動で部屋一覧へ遷移し、他参加者にシステムメッセージで通知 | ◯ |
| SNS シェア | 部屋作成時・作成後に X / Discord へ参加リンクを投稿。1 部屋・1 時間あたり 3 回まで | ◯ |
| 評価機能 | 退出後 24 時間以内に同室参加者を星評価（任意・匿名・送信後変更不可） | ◯ |
| 評価表示 | ユーザープロフィールおよび参加前プレビューに累積評価スコアを表示 | ◯ |
| アカウント削除 | 退会機能 | ◯ |
| 通報・ブロック | 悪質ユーザーへの対応 | ✕（MVP 後） |

### 2.2 認証・アカウント設計

#### ログイン方式

| プロバイダ | MVP |
|----------|-----|
| Google OAuth 2.0 | ◯ |
| X (Twitter) OAuth 2.0 | ◯ |
| Discord OAuth 2.0 | ◯ |

- 複数プロバイダを同一アカウントに連携（マージ）可能
- ゲスト利用は募集リンク経由の部屋参加のみ可。部屋作成・評価・プロフィール編集には認証必須

#### ゲストセッション

| 項目 | 仕様 |
|------|------|
| 発行条件 | 募集リンク経由で部屋参加時 |
| 識別子 | サーバーが発行する一時 ID（例：`guest_xxxxxxxx`） |
| 表示名 | 参加時に入力画面を表示。初期値はゲスト ID |
| 保存場所 | Redis（TTL: 24 時間）+ Cookie（HttpOnly） |
| 有効期限 | 24 時間。期限切れ後は再参加時に新規発行 |
| 重複参加防止 | Cookie ベースで同一セッションを識別し同一部屋への重複参加を防ぐ |

#### 初回ログインフロー

```
ソーシャルログイン完了
    ↓
プロフィール設定画面（ユーザー名のみ必須・他は任意）
    ↓
設定完了 → 元の画面へリダイレクト
```

- OAuth の `state` パラメータに遷移元 URL を保持し、プロフィール設定後に元 URL へリダイレクトする
- ユーザー名設定前は部屋への参加・作成・チャットを利用不可

#### 招待リンク仕様

- 部屋作成時に招待トークン（64文字の hex 文字列）を自動生成する
- ホストは部屋詳細画面の InvitePanel からリンクをコピーして共有できる（生成・無効化ボタンは不要）
- トークンは部屋が `closed` になるまで有効

#### 招待URL経由の参加フロー

招待URL（`/rooms/[roomId]?inviteToken=xxx`）へのアクセス時は以下のフローを取る。

| 状態 | フロー |
|------|--------|
| 未ログイン | Modal A（認証誘導）を表示。「ログインして参加」または「ゲストで参加」を選択 |
| `guestFlow=true` クエリパラム付き | Modal B（表示名入力）を表示。ゲストセッションを発行してチャットへ遷移 |
| ログイン済み（既存ユーザー） | モーダルなし。通常の参加ボタン（RoomActions）で参加 |
| 招待URL経由の新規OAuthログイン | `needsProfileSetup=true` を検知し、招待ページに `error=new_user` で戻す。Modal A（エラー表示）でゲスト参加またはオンボーディングへ誘導 |

- 招待URL経由での新規アカウント登録（OAuthによる初回参加）は不可。ゲスト参加を推奨
- 「ログインして参加」は既存アカウント保有者向け

#### プロフィール項目

| 項目 | 必須 / 任意 | 備考 |
|------|-----------|------|
| ユーザー名 | 必須 | 重複許可（識別は User ID で行う） |
| アイコン | 任意 | 未設定時はデフォルトアイコン |
| 自己紹介 | 任意 | テキスト形式 |
| ゲームタイトル | 任意 | 複数設定可 |
| Discord Webhook URL | 任意 | 登録は 1 サーバーまで。SNS シェア時に使用（**未実装**：DB 列のみ存在し、設定 API・投稿機能ともに未提供） |

### 2.3 部屋のライフサイクル管理

#### ステータス定義

| ステータス | 説明 |
|-----------|------|
| 募集中 | 参加者を受け付けている状態 |
| 満員 | 最大人数に達した状態。参加不可・閲覧のみ |
| 終了 | ホストが手動で終了した状態 |

#### ステータス遷移

```
募集中
  ↓ 最大人数到達で自動遷移
満員
  ↓ 参加者が退出し空きが出た場合、自動復帰
募集中
  ↓ ホストが手動で終了操作
終了
```

- 空き部屋の自動クローズは設けない（ホストが手動で閉じるまで存続）
- 終了後はリンクを即時無効化

#### ホスト離脱時の挙動

| ケース | 挙動 |
|--------|------|
| ログイン済み参加者がいる場合 | 最も早く参加したログイン済みユーザーへ自動引き継ぎ |
| 参加者が全員ゲスト または 0 人の場合 | 部屋を自動終了 |

#### 部屋情報の編集制限

| 項目 | 編集可否 |
|------|--------|
| 募集文 | ◯ |
| ゲームタイトル | ◯ |
| プレイスタイル | ◯ |
| 部屋名 | ◯ |
| 最大人数 | ✕（作成後変更不可） |

#### 終了後のデータ管理

- 終了した部屋は一覧から非表示
- 評価完了まで部屋データを DB に保持

### 2.4 SNS シェア機能

> **⚠️ 本節は未実装（設計のみ）。** 現状の招待・共有は、サーバー発行の招待トークン付きリンク（`POST /api/v1/rooms/:id/invite`）を手動で共有する方式のみ。X Share API / Discord Webhook への自動投稿、投稿テンプレート、投稿回数制限は未実装。

#### 投稿仕様

- 部屋作成時に X・Discord・両方を選択して即時投稿（任意）
- 部屋作成後も再投稿可能
- **投稿回数制限：1 部屋につき 1 時間あたり 3 回まで**

#### 投稿テンプレート

テンプレート構造は固定。自由入力欄（募集文）のみ編集可能。

```
【{ゲームタイトル} / {プレイスタイル}】
{募集文}（自由入力・デフォルトは部屋作成時の募集文）
残り {残り枠数} 枠 👉 {参加リンク URL}
#QuestLink
```

- 募集文の文字数制限は部屋作成時の募集文と同一

#### 各プラットフォームの投稿方式

| プラットフォーム | 方式 |
|---------------|------|
| X | X Share API 経由 |
| Discord | プロフィールに登録した Webhook URL 経由（1 サーバーまで） |

#### リンク仕様

- URL 形式：`https://questlink.gg/rooms/{room_id}`
- 有効期限：部屋が「終了」になるまで有効
- 終了と同時に無効化
- 満員時：参加者一覧の閲覧のみ可

### 2.5 参加前プレビュー画面

ログイン不要で閲覧可能。WebSocket なし（画面更新時のみ最新化）。

#### 表示情報

| 項目 | 内容 |
|------|------|
| 部屋情報 | ゲームタイトル・プレイスタイル・現在の参加人数 / 最大人数・ステータス・募集文 |
| ホスト情報 | ユーザー名・評価スコア |
| 参加者一覧 | ユーザー名・アイコン・評価スコア。ゲスト参加者は「ゲスト」と表示し評価スコアは非表示 |

#### 評価スコアの表示ルール

- 評価件数が 5 件以上：★4.2 / 128 件 の形式で表示
- 評価件数が 5 件未満・新規ユーザー：「評価なし」と表示

- WebSocket はゲスト・ログイン済みを問わず部屋参加者のみ提供（チャット専用）
- ゲストの WebSocket 接続はゲストセッション ID で識別・認可する

### 2.7 評価システム

#### 評価形式

| 項目 | 仕様 |
|------|------|
| 形式 | 1〜5 の星評価 |
| 対象 | 同室のログイン済み参加者のみ（ゲストは評価の送受信対象外・自己評価は除外） |
| 匿名性 | 完全匿名 |
| 変更・削除 | 不可 |
| 評価期限 | 退出後 24 時間以内 |
| スキップ | 可能（任意） |

#### スコア集計・表示

| 項目 | 仕様 |
|------|------|
| 集計方法 | 1〜5 の単純平均（小数点第 1 位まで） |
| 表示形式 | ★4.2 / 128 件 |
| 5 件未満 | 「評価なし」と表示 |

#### リマインド

次回ログイン時にアプリ内バナーで未評価セッションを通知。

#### 不正対策

- 同一セッション内での重複評価を禁止（1 人 1 回のみ）
- 自己評価をシステムレベルで排除

### 2.8 ゲーム選択画面（`/games`）

ゲームを選択してゲーム別部屋一覧（`/games/{gameId}/rooms`）へ進む画面。ログイン不要で閲覧可能。

#### ゲームマスター管理

| 項目 | 仕様 |
|------|------|
| データソース | `games` テーブルから直接取得。運営が事前に登録したマスターデータのみが対象 |
| 登録・追加 | 運営のみ実施。ゲーム名・カバー画像 URL・ジャンルを直接 DB に登録 |
| MVP 登録数 | 20〜30 タイトル |
| 画像の扱い | カバー画像 URL をマスター DB に保持し、表示時は URL を直接参照 |

#### マスターデータ構成

| フィールド | 内容 |
|-----------|------|
| game_id | 自社採番 ID |
| igdb_id | 任意の外部参照 ID（運営作業時の参照用。NULL 可） |
| name | ゲーム名 |
| cover_image_url | カバー画像 URL |
| genre | ジャンル（FPS / RPG / MOBA / etc） |

#### 画面仕様

- ゲームタイトルをサムネイル画像＋ゲーム名のカード形式でグリッド表示
- MVP（20〜30 タイトル）はグリッド表示のみ。タイトル数増加後にジャンルタブ等の絞り込みを検討
- 部屋作成・プロフィールのゲームタイトル設定も同マスターから選択

### 2.9 部屋一覧フィルター・検索

#### フィルター仕様

| フィルター | 種別 | 仕様 |
|-----------|------|------|
| プレイスタイル | タグ選択 | カジュアル / ランク重視 / 初心者歓迎 / 上級者限定。複数選択可（AND 検索） |
| 空き枠あり / なし | トグル | ON で募集中ステータスの部屋のみ表示 |
| フリーワード | テキスト入力 | 部屋名・募集文を対象にあいまい検索 |

#### URL 設計

フィルター条件を URL パラメータに持たせブックマーク・共有可能にする。

```
/games/1/rooms?style=casual&vacant=true&q=初心者
```

#### 並び順

デフォルトは新着順（`created_at DESC`）固定。

#### フリーワード検索の実装方針

| Phase | 方式 |
|-------|------|
| Phase 1 | PostgreSQL の `tsvector` + `GIN` インデックスによる全文検索 |
| Phase 2 以降 | 負荷状況に応じて Elasticsearch 等への移行を検討 |

#### 文字数制限

| 項目 | 上限 |
|------|------|
| 部屋名 | 50 文字 |
| 募集文 | 300 文字 |

## 3. 非機能要件

### パフォーマンス（Phase 1）

| 指標 | 目標値 |
|------|-------|
| MAU | 1 万 |
| DAU | 2 千 |
| ピーク RPS | 50 |
| 同時接続数 | 100〜500 |

- WebSocket の同時接続は数百規模。単一サーバーでも対応可能な水準
- Phase 2（MAU 10 万・同時接続 5,000）への移行を意識したスケールアウト可能な設計を心がける

### レスポンシブ対応

PC・モバイルブラウザの両方で快適に操作できるレスポンシブデザインを必須とする。ネイティブアプリ（iOS / Android）は対象外。

## 4. セキュリティ

### 認証方式

| 項目 | 仕様 |
|------|------|
| 認証方式 | OAuth 2.0（Google / X / Discord） |
| セッション管理 | NextAuth.js v5 の JWT セッション（サーバーサイドのセッションストアは持たない）。ログイン済みとゲストを分離管理。WebSocket 接続時は有効期限 60 秒の短命 JWT を別途発行 |
| ゲスト利用 | 募集リンク経由の部屋参加のみ可。ゲストセッションは TTL 24 時間の署名付き Cookie（`quest_link_guest_session`）＋ DB の参加レコードで認可（Redis は使用しない） |
| 複数プロバイダ連携 | 同一アカウントへの複数 OAuth プロバイダの紐づけに対応 |

### その他セキュリティ要件

| 項目 | 仕様 |
|------|------|
| 通信 | 全通信を HTTPS / WSS で暗号化 |
| 入力バリデーション | サーバーサイドでスキーマバリデーション |
| レート制限 | API エンドポイント全般にレート制限を適用（SNS 投稿の 1 部屋・1 時間あたり 3 回は SNS シェア機能が**未実装**のため対象外） |
| 評価の整合性 | 重複評価・自己評価をシステムレベルで制御 |
| Webhook URL の検証 | Discord Webhook URL の形式バリデーションを実施（**未実装**：SNS シェア機能に付随） |
| リンク無効化 | 部屋終了と同時に参加リンクを無効化 |
